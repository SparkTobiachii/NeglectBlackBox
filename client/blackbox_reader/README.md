# Neglect Black Box reader (Windows)

Logger for staff PCs. Reads `%LOCALAPPDATA%Low\VRChat\VRChat\output_log_*.txt`, sends **events only** (never the log, never a VRChat login) to the bot, and only while the person is in an instance of the group. No actions, no moderation.

## For staff (install and use)
1. Get `NeglectBlackBox-Setup.exe` from the DEV owner and run it (no admin rights needed). It installs per user, starts the reader and adds it to Windows autostart.
2. Your browser opens once: log in with Discord. That proves who you are (only staff can link a PC).
3. The DEV owner approves your PC in the dashboard (Black Box > Devices). From then on it records by itself whenever you are in a group instance; leaving the instance, closing or crashing VRChat ends it.
4. **Ctrl+Shift+N** shows or hides the program window (dark, Neglect colours; since 0.5.1 drawn on one canvas with rounded cards, a gradient background with a crimson glow, glossy 3D buttons that sink when pressed, a lit status bead and a big status line; keyboard use with Tab / Shift+Tab, Enter / Space and a gold focus ring; the height follows the content, the width is 580; if the drawing fails the window falls back to the plain layout and the logger keeps running). It has no button in the taskbar and the X only hides it, so the logger keeps running. It shows what the logger does and has **Stop logging** (nothing is read or sent until you press **Start logging**; this survives a restart), **Check for updates** and a small **Exit completely**.
   - Ctrl+Shift+N is also the "new private window" shortcut of Chrome and Edge. While the reader runs, the reader gets it. Change it in `%APPDATA%\NeglectBlackBox\settings.json` (`"hotkey": "ctrl+alt+b"`), then restart the reader. When the keys are taken by another program the window opens once and the Start menu entry "Neglect Black Box" opens it.
   - **Avatar IDs (since 0.5.0, off by default, opt-in on both sides).** VRChat itself writes the `avtr_` IDs of the avatars its client loaded into its analytics file `%TEMP%\VRChat\VRChat\amplitude.cache`, in load order. The reader can read that file for the IDs and send them to the bot. It only works when BOTH switches are on: the DEV owner's switch (dashboard > Black Box > Devices > Avatar IDs) AND yours. Yours is the button **Read avatar IDs** in the window; it appears only while the DEV owner has allowed the feature, and the choice is saved in `settings.json` (`"avatar_ids": true`). **Stop logging** also stops it.
   - What is read and sent: of that file only the matched `avtr_<uuid>` strings (the file holds personal data, everything else is ignored and never leaves the PC), one event per ID, only for the room the IDs belong to and only for instances of the group. The history already in the file when the reader first looks is never sent. No third-party database, no extra host. The bot keeps the events 30 days.
   - Debug log line (UNVERIFIED): when VRChat is started with `--log-debug-levels=API` (Black Box start options / the "VRChat (Black Box)" shortcut), the reader also turns the log line `[API] Requesting Get avatars/<avtr_id>` into an avatar ID event (only while the room is tracked, once per ID per room, and only while both avatar ID switches are on). The exact line format comes from reports of other tools and has not been seen in a real log of ours yet; it is not known whether VRChat writes it for other players' avatars.
   - The avatar database (IDs with name and creator) lives on the bot server only; nothing of it is stored or sent back to the PC.
   - Limits: VRChat writes the file when it changes the room (12 - 28 s after entering the next room), so IDs arrive late, not live; only avatars that were loaded appear; there are no player names.
5. The program **updates itself**: every 5 minutes it asks the bot, and installs a newer version silently (only when the SHA-256 of the installer matches). The button checks at once.
6. Uninstall: Windows Settings > Apps > Neglect Black Box. Data folder: `%APPDATA%\NeglectBlackBox` (`reader.log`, `settings.json`).

## For the DEV owner (release and updates)
The reader lives in the **public** repository `SparkTobiachii/NeglectBotDashboard` (this folder and `neglect/blackbox_parse.py` are the same files as in the bot repository; the bot repository is the master, copy changes over). Nothing needs a secret:
1. Raise `VERSION` in `reader.py` and push to `main` of NeglectBotDashboard. The workflow `Black Box reader (Windows)` starts by itself (or by hand: Actions > Run workflow). It builds `NeglectBlackBox.exe` (PyInstaller, Python + Tk bundled, no console window), runs `selftest` on it, builds `NeglectBlackBox-Setup.exe` (Inno Setup, `installer.iss`), prints the SHA-256 and makes the GitHub release `blackbox-v<version>` with the installer and `SHA256SUMS.txt`.
2. The bot looks at the latest release every few minutes (when a reader reports in), downloads the installer itself, checks the SHA-256 against `SHA256SUMS.txt` and offers it to every PC at once. The PCs ask the bot for the installer (signed request), so older readers update too.
3. **By hand** (if GitHub is not reachable): dashboard > Black Box > Devices > Reader update, enter the version and pick `NeglectBlackBox-Setup.exe`. With "Offer a new upload to every PC at once" switched off, a new version waits for the button "Offer it now" (this also stops the automatic pick-up from GitHub).
4. Readers install only a version that is newer than theirs, only from the bot (signed request) or from `github.com/SparkTobiachii/NeglectBotDashboard/releases/download/`, and only when the SHA-256 matches.

## Developing
- `reader.py run | show | selftest`; needs `PyNaCl` (and `tkinter` for the window, Windows only); the parser is `neglect/blackbox_parse.py` (shared with the bot, no other bot code). The window code is `bb_window.py`, the assets (logo, icon, installer images) are in `assets/`.
- Tests: `tests/test_blackbox_reader.py` (state machine, update rules, window logic with a stand-in for tkinter; run on Linux). The Windows parts (DPAPI, hotkey, tray-less window, registry autostart, installer) can only be tried on Windows.
- `cache_probe.py`: read-only probe of the VRChat avatar cache. Prints a report; nothing is sent.
- Window preview: `python client\blackbox_reader\bb_window.py` (Windows, needs tkinter) shows the window with made-up data, no reader and no network, for a look at the design. The 0.5.1 drawing was only tested with a fake canvas on Linux; the real look on Windows is not verified yet.
- `amplitude_probe.py`: standalone read-only test script (no network code, not bundled into the exe). It watches `amplitude.cache`, prints and reports only the `avtr_` IDs (masked unless `--full-ids`), counts and timestamps, and follows the newest VRChat log (only room changes, `Unpacking Avatar (Name by Creator)` lines and join / leave counts) to compare the order. Run on Windows while VRChat runs: `python amplitude_probe.py watch --full-ids` (20 minutes, `--minutes 40` for longer, `--no-log` without the log) or `python amplitude_probe.py once`; type a number + Enter to set a marker; the report is `amplitude_probe_report.txt` next to the script (check it before you send it). It also notes the debug log lines `[API] Requesting Get avatars/<id>` in its timeline and counts them in the report ("API avatar request lines in the log", only present when VRChat was started with `--log-debug-levels=API`). With `--structure` (`python amplitude_probe.py watch --structure`) the report also lists the KEY NAMES of `amplitude.cache` with the kind of value each holds and the event names, never a value, and the ID kinds (`usr_` / `wrld_` / `file_` / `grp_`) of the largest snapshot as numbers only. It never changes or clears the file. Tests: `tests/test_amplitude_probe.py`.
- `AmplitudeTail` / `Reader.id_room` / `Reader.feed_ids` in `reader.py` carry the avatar ID feature; the extractor `avatar_ids_from` is shared with the bot in `neglect/blackbox_parse.py`. Tests: `tests/test_blackbox_reader.py`. Not tried yet on a real Windows exe.
